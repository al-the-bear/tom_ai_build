root is the typed head of one TomSpecs document; the sections beneath it are
catalogued by the generated outlines rather than repeated here (see below).

For task-oriented guidance see [document_roots.md](../package/document_roots.md).

## Overview

A specification is **one document with fourteen entry points**. `DocSpecsProject`
gives them a single true root so an editor can load, serialize, snapshot and undo
the whole specification by operating on one object.

a second thing to keep current.

## Classes

### DocSpecsProject

The canonical container root of the whole object model. **Not a document node:**
it carries no `@SectionId` and no `@Document`, because it is the tree root the
tooling walks rather than a fifteenth sibling. Tooling treats it as the canonical
root and exempts it from section-id coverage and uniqueness.

**Extends:** `DocSpecsSection`

#### Constructors

```dart
DocSpecsProject();
```

Constructing it registers the generated snapshot/serialization ops (idempotent),
so the save paths and the snapshot engine work without `dart:mirrors`.

#### Methods

| Method | Return Type | Description |
|--------|-------------|-------------|
| `toYaml({required SomMetaTree tree, String? modelVersion})` | `String` | The global save: the Solution Blueprint master alone. Because the projections are views over the same sections, the output never duplicates a subtree. `tree` must be the metadata tree of `D00SolutionBlueprint`. |
| `toYamlForRoot(Object root, {required SomMetaTree tree, String? modelVersion})` | `String` | The per-root save. For `solutionBlueprint` this is `toYaml`; for a projection it runs the connect pass first, re-pointing the projection onto the live master. `tree` must be the metadata tree of **`root` itself**. |
